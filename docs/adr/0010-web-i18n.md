# 0010 — Web internationalisation: react-intl (FormatJS) with an extract/verify pipeline

## Context and problem statement
AGENTS.md §3.6 requires that all UI strings are externalised in ICU MessageFormat from day one, that the product supports multiple languages including right-to-left scripts, and that hard-coded strings are caught (pseudo-localisation, TESTING_STRATEGY §4). Research: `epic-03-web-foundation/research.md §R12`.

## Considered options
1. react-intl (FormatJS)
2. i18next + i18next-icu
3. Lingui

## Decision outcome
Chosen option: **react-intl 12 + @formatjs/cli**.

**Message ids and source locale**
- Ids are explicit and namespaced by feature (`health.title`). Messages are declared with `defineMessages` next to the components that use them.
- `en` is the source locale. `pnpm i18n:extract` writes `src/i18n/messages/en.json` from the source code, and CI fails if the file is stale.
- Other locales are files in the same folder. `pnpm i18n:verify` checks them for missing keys and ICU structural equality.

**Pseudo-localisation**
`pnpm i18n:pseudo` generates two pseudo-locales from `en`:
- `xx-LS`: accented and about 30–40 % longer;
- `en-XB`: bidi.

They are selectable in dev and e2e builds and never offered in production.

**Locale and direction**
- The locale comes from the user's choice, then the browser. Tenant defaults arrive in Phase 1a.
- `<html lang dir>` follows the locale. The direction comes from `Intl.Locale#getTextInfo()`, with a fallback list (`ar`, `he`, `fa`, `ur` → `rtl`).
- `ar` is wired from the start to prove RTL. Real pilot translations come in Phase 3.

**Formatting**
- Dates and numbers are formatted with `Intl` through react-intl. Timestamps arrive in UTC and are rendered in the user's time zone (§3.6).

### Consequences
- Good: hard-coded strings are caught by lint (ADR-0009) and by pseudo-locale e2e runs; message ASTs are precompiled.
- Bad: every UI string needs an id, which is deliberate.

### Confirmation
- lint;
- `i18n:extract` drift check;
- `i18n:verify`;
- pseudo-locale e2e run (nightly);
- RTL screenshots.
