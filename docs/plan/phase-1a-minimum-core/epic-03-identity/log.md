# E03 Identity, sessions and step-up — log

## 2026-10-18

- Findings: Spring Security 7.1 has a factor model (`FactorGrantedAuthority` with `issuedAt`, `validDuration`) that fits MFA and step-up, but its flows are redirect-based, so the SPA gets JSON endpoints; Spring Session's cleanup is a `@Scheduled` cron, replaced by a db-scheduler task; the session stores a small JSON principal of ours instead of a serialised `SecurityContext`.

## 2026-10-25
- T1 done: tenant from the request host (`TenantResolutionFilter`, single-tenant and fallback modes, Caddy `ask` endpoint `tenanthost` on the management port).
- T2 done: `identity_user`/MFA/recovery/action-token tables with RLS; `UserAccounts` (create, set password, match with re-hash on outdated encoding); Argon2id via Bouncy Castle with PBKDF2 as the FIPS option; length-only policy (tenant minimum, never below 8) with a bundled Bloom filter of the SecLists top one million (1.7 MB, 0.1 % false positives, rebuilt by `updateBreachedPasswords` from the SHA-256-pinned list) plus optional customer-mounted HIBP range files; demo users with `MEMO_DEMO_PASSWORD` (generated by `scripts/dev.mjs` and `gen-secrets.sh`).
- Audit action names allow only `[a-z0-9_]` segments, so `identity.user.password.set`, not `password-set`.
- `deploy/scripts/gen-secrets.sh` changed: re-run Ansible on the dev VM after merge so `MEMO_DEMO_PASSWORD` is generated there.
- Owner decision (dev email): a mail catcher (Mailpit) on the dev VM, reachable only through an SSH tunnel, for now; a real SMTP relay later, so the relay stays configuration (`memo.mail.*`).
- T3 (login and sessions), decisions made while building:
  - Session ids are 256-bit random strings (`RandomSessionIds`); Spring Session's default UUIDs carry only 122 bits (ASVS V7.2.3 asks for 128), so the session tables use `text` ids.
  - Session attributes are strings only (`StringOnlySessionAttributes`): the principal JSON and its index name. Any other attribute fails loudly; this caught Spring Security's test `csrf()` post-processor, which swaps in a session-backed token store, so tests fetch a real token from `/auth/csrf` like the SPA.
  - The session cookie is a `DefaultCookieSerializer` bean (`MEMO_SESSION`, HttpOnly, Secure, SameSite=Lax, host-only): Boot applies `server.servlet.session.cookie.*` to Spring Session only with an embedded server, and the tests showed a bare `SESSION` cookie without those attributes.
  - The principal carries `tenantAdmin`, `mfaRequired` and an absolute `expiresAt` fixed at sign-in, so a request needs no query beyond the session lookup; changing a user's role or MFA requirement revokes their sessions (T8).
  - `ActorContextFilter` stays first (anonymous actor for everything before security); `UserActorFilter` inside the security chain rebinds the actor to the signed-in user.
  - Problem `type` URIs are URNs (`urn:memo:problem:invalid-credentials`, `…:mfa-required`, …): stable identifiers, not links.
  - Partial sessions (password only, MFA outstanding) get 401 `mfa-required` on everything but the auth endpoints.
- T4 (rate limits and lockout):
  - Lockout answers stay uniform (401 `invalid-credentials`); the client message mentions both causes. Throttle 1 min doubling to 15 after 5 failures (attempts during a wait are neither evaluated nor counted), lock for 30 min after 20, lifted at the next successful sign-in after expiry (audited as `identity.user.unlocked` by `System(lockout)`).
  - The per-account limit (10 per 15 min) applies to unknown emails too, so a 429 says nothing about whether an account exists.
  - Trusted forwarded headers (a T1 leftover): `server.forward-headers-strategy=native` (Tomcat RemoteIpValve, private ranges trusted). nginx now sets `X-Forwarded-Host` from `$host` and drops `X-Forwarded-Port`, so a client cannot choose the tenant host through a forwarded header.
  - Tests give every sign-in a random TEST-NET client address: test classes share the database, and a shared 127.0.0.1 would exhaust the per-IP limit across classes.
- T5 (TOTP MFA):
  - `identity_mfa` keeps the active secret and a pending one in separate columns, so re-enrolling never drops a working authenticator before the new one is confirmed. V1 was changed in place: it has not been merged or deployed anywhere.
  - Secrets are AES-256-GCM encrypted by `DataKeys` (HKDF-SHA256 over `MEMO_DATA_KEY`), bound to tenant and user through the associated data. The web application refuses to start without the key; migrate mode needs none. The key is generated by `scripts/dev.mjs` and `gen-secrets.sh`, a Kubernetes Secret (`security.dataKeySecret`) in Helm.
  - A partial session (password only) may enrol only an account that has no MFA yet; changing an existing authenticator needs a complete session.
  - The MFA policy setting takes `all` (default) or `admins`, as ADR-0024 says; T3 had used true/false.
  - Demo users get `MEMO_DEMO_TOTP_SECRET` (Base32) so Playwright can compute their codes (T10).
- T6 (step-up), decisions:
  - `StepUp.require()` checks the session's strongest factor: TOTP when the session has one, the password otherwise (users of an `admins`-only tenant have no TOTP). `/auth/step-up` takes a code or the password accordingly and refreshes that factor under a new session id.
  - The `/me` endpoints of design §3 came with T6, as the first sensitive actions: `GET /me`, `PUT /me/password` (step-up, signs out every other session), `POST /me/recovery-codes` (step-up), `GET /me/sessions`, `DELETE /me/sessions/{id}`.
  - Sessions are listed by an opaque handle (SHA-256 prefix of the session id), never the id itself, which is the cookie value. Each session records the client address, user agent and sign-in time at sign-in (`memo.client`).
  - Validation problems carry `errors: [{field, code, message}]`; `code` (for example `TOO_SHORT`, `INCORRECT`) lets the web client translate.
- T7 (invitations, password reset, mail), decisions:
  - One-time tokens never appear in URLs: emailed links carry them in the fragment (`/invitation#<token>`, `/reset-password#<token>`), which browsers do not send, and the API takes them in POST bodies (`/auth/invitations/lookup`, `/auth/invitations/accept`, `/auth/password-reset/complete`) instead of the design's `GET /auth/invitations/{token}`. Request lines and proxy access logs stay free of secrets.
  - Mail outbox (`notification_mail_outbox`, tenant table): template parameters can hold those links, so they are encrypted with `DataKeys` and cleared once sent. Delivery is a db-scheduler tenant task scheduled in the business transaction (the starter wraps the DataSource in `TransactionAwareDataSourceProxy`), retried 8 times; no SMTP host means the mail stays PENDING.
  - A weak password is rejected before the link is used up, so the user can try again with the same link.
  - Sign-in alert: a returning user signing in from a user agent none of their current sessions has.
  - Links use `memo.tenancy.public-url-template` (`MEMO_PUBLIC_URL_TEMPLATE`, `{slug}` placeholder; default `https://{slug}.<base domain>`).
  - Found and fixed while wiring mail: the T1 tenancy settings (`MEMO_TENANCY_*`) were not passed through by Compose, Helm or Ansible, so a deployed backend would have defaulted to base domain `localhost`. Compose now requires `MEMO_TENANCY_BASE_DOMAIN`; Ansible sets it per environment with `demo` as fallback, plus Mailpit (`devtools` profile, UI on the VM's loopback) as the mail catcher. Re-run Ansible before merging.
- T8 (user administration API), decisions:
  - `/api/v1/admin/**` needs `ROLE_TENANT_ADMIN`, which a session gets only when complete; a partial admin session gets 401 `mfa-required`, a user 403.
  - Lifecycle actions are guarded updates on id, allowed statuses and the `If-Match` version: no header 428, stale 412, wrong status 409 `reason: STATUS`. Self-deactivation 409 `SELF`; the last active admin 409 `LAST_ADMIN` (admin rows are locked `FOR UPDATE` during the check, so two admins cannot deactivate each other at once). Deactivation and MFA reset sign the user out everywhere; deactivation retires open links.
  - `Idempotency-Key` is a small reusable service in the `system` module (`system_idempotency_key`, tenant table): the key row is inserted first, so a concurrent repeat waits for the first commit and returns its result; a different body under the same key is 422.
  - Test passwords skip the ~0.1 % of random strings the breached-password Bloom filter flags (CI hit one: a reset with a "breached" random password returned 400).
