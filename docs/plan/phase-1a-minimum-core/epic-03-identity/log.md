## 2026-10-25

- T2 done: `identity_user`/MFA/recovery/action-token tables with RLS; `UserAccounts` (create, set password, match with re-hash on outdated encoding); Argon2id via Bouncy Castle with PBKDF2 as the FIPS option; length-only policy (tenant minimum, never below 8) with a bundled Bloom filter of the SecLists top one million (1.7 MB, 0.1 % false positives, rebuilt by `updateBreachedPasswords` from the SHA-256-pinned list) plus optional customer-mounted HIBP range files; demo users with `MEMO_DEMO_PASSWORD` (generated by `scripts/dev.mjs` and `gen-secrets.sh`).
- Audit action names allow only `[a-z0-9_]` segments, so `identity.user.password.set`, not `password-set`.
- `deploy/scripts/gen-secrets.sh` changed: re-run Ansible on the dev VM after merge so `MEMO_DEMO_PASSWORD` is generated there.
- Owner decision (dev email): a mail catcher (Mailpit) on the dev VM, reachable only through an SSH tunnel, for now; a real SMTP relay later, so the relay stays configuration (`memo.mail.*`).
- T3 (login and sessions), decisions made while building:
  - Session ids are 256-bit random strings (`RandomSessionIds`); Spring Session's default UUIDs carry only 122 bits (ASVS V7.2.3 asks for 128), so the session tables use `text` ids.
  - Session attributes are strings only (`StringOnlySessionAttributes`): the principal JSON and its index name. Any other attribute fails loudly; this caught Spring Security's test `csrf()` post-processor, which swaps in a session-backed token store, so tests fetch a real token from `/auth/csrf` like the SPA.
  - The session cookie is a `DefaultCookieSerializer` bean (`MEMO_SESSION`, HttpOnly, Secure, SameSite=Lax, host-only): Boot applies `server.servlet.session.cookie.*` to Spring Session only with an embedded server, and the tests showed a bare `SESSION` cookie without those attributes.
  - The principal carries `tenantAdmin`, `mfaRequired` and an absolute `expiresAt` fixed at sign-in, so a request needs no query beyond the session lookup; changing a user's role or MFA requirement revokes their sessions (T8).
  - `ActorContextFilter` stays first (anonymous actor for everything before security); `UserActorFilter` inside the security chain rebinds the actor to the signed-in user.
  - Problem `type` URIs are URNs (`urn:memo:problem:invalid-credentials`, `…:mfa-required`, …): stable identifiers, not links.
  - Partial sessions (password only, MFA outstanding) get 401 `mfa-required` on everything but the auth endpoints.
