# E05 Files service — log

## 2026-11-02
- E04 merged and deployed; nightly green. Plan written: research, ADR-0028 (envelope encryption) and ADR-0029 (upload pipeline and range downloads), design, threat model, tasks, test plan. Gate delegated (overview Q1).
- Findings:
  - **Encryption:** Tink streaming AEAD (1.24.0) with one keyset per tenant, wrapped by a KEK from a `KeyProvider`. The 1a software provider derives the KEK from `MEMO_DATA_KEY` with its own HKDF label, so no new secret. 64 KiB ciphertext segments (a supported custom parameter, checked in the 1.24.0 jar) keep a 64 KiB range read to at most two segments.
  - **Pipeline:** one pass over the body (SHA-256, clamd `INSTREAM`, encryption into a local ciphertext spool), inspection by decrypting the spool, upload only after acceptance. Nothing rejected reaches storage, which matters because `records` objects cannot be deleted. Record objects get a 7-day provisional lock that is extended after the database commit, so a failed commit cannot leave an orphan locked for 10 years.
  - **Plaintext traps found:** Spring multipart temp files, nginx request buffering, and PDFBox scratch files. Multipart is disabled, the upload route streams, and PDFBox runs memory-only with a cap. Both nginx and Caddy currently cap bodies at 1 MB; the upload route gets the ceiling.
  - **Detection:** Tika 4.1.0 core + zip-commons. Tika's OOXML detector needs Apache POI, so we read `[Content_Types].xml` ourselves (fuzzed) to tell DOCX from DOCM. Legacy `.doc`/`.xls`/`.ppt` are not allowed by any 1a purpose; Phase 2 decides.
  - **ClamAV:** heuristics are off by default; our `clamd.conf` turns on `AlertExceedsMax`, `AlertEncrypted`, `AlertOLE2Macros`, `AlertBrokenExecutables`. No maintained Java clamd client exists, so we own a small one.
  - **Dev VM memory (Q7):** 1.6 GiB used, 6.3 GiB available of 7.8 GiB. ClamAV needs over 1.2 GiB and peaks above 2.4 GiB during the daily reload, so it fits with the default concurrent reload.
- No screens in E05: the upload component is built with E07's branding page, its first user.
- T1 done (keysets): one Tink keyset per tenant, created in its own transaction (`ON CONFLICT`, four racing nodes end with one row, audited once) and refused inside a caller's transaction, so an uncommitted keyset is never cached. Tink 1.24 deprecates the encrypted-keyset calls without a `Configuration`; we pass `StreamingAeadConfig2026`.
- T2 done (object store): `ObjectStore` replaces `RecordStore`. Against SeaweedFS 4.48 the `app` identity cannot delete a locked version, shorten or bypass its lock, **or change GOVERNANCE to COMPLIANCE**, so the provisional lock is written in the final mode and only its date is extended later. An "overwrite" of a locked key only adds a version.
- T3 done (clamd): our client and a strict reply parser; the clamd settings live in `deploy/clamav/clamd.env` (`CLAMD_CONF_*` variables the official image writes into its config) for Compose, Helm and tests; the test scanner uses the `_base` image with two tiny signature files and starts in seconds. clamd reports custom signatures with an `.UNOFFICIAL` suffix.
- T4 done (inspection): Tika's zip-container detector was dropped after reading it: it can spool the stream to a temporary file through `TikaInputStream.getPath()`. Tika magic alone already names OOXML and ODF packages; our zip reader (Commons Compress over the decrypting channel) does the rest.
- T5 done (upload API): detekt's defaults (two throws per function, eleven functions per class) shaped the code: rejections go through `reject(...)`, pending uploads have their own store. Tink's keyset-level decrypting channel cannot report its size before the first read; `FileCrypto.decrypting` primes it. Object-lock dates are whole seconds, so retention dates are rounded up. Full backend suite: 745 tests green.
- T6 done (downloads): reads and retention changes now address the storage version recorded at upload (`files_version.object_version`), found while writing the tamper test: in a versioned bucket a newer object under the same key would otherwise shadow the record. Single ranges, 416, multi-range as 200, `If-Range`, `If-None-Match`, `HEAD`; the open marker lives in the server-side session. The logo's public caching is left to E07's own endpoint.
- Environment: Docker Desktop's VM clock ran 22 s behind the host after the machine slept, which made the lock-expiry test flaky; it now uses the storage server's `Date` header. CLI builds use `MEMO_BUILD_ROOT=.build-cli/e05` because a killed test JVM left a handle open in the default build root.
- T7 done (retention and sweeps): `files-retention-sweep` (5 min) and `files-pending-sweep` (hourly) fan out to tenant tasks. Tenant setting keys allow only dots (`files.upload.max.bytes`, `files.records.retention.mode`, `files.records.retention.years`); the design had dashes. Leftover removal is audited; a lock the job cannot extend is counted in `memo.files.retention.still.provisional`.
- T8 (corpus and fuzzing): the corpus found that a 200 MiB zip bomb (200 KiB on disk) was **accepted**: ClamAV 1.5.4 trims a compressed entry larger than `MaxFileSize` to the limit and scans only that, without the `Heuristics.Limits.Exceeded` alert, even with `AlertExceedsMax yes` (checked with `clamscan --debug`). The zip reader now refuses bombs from the central directory (entry over 1 MiB compressed more than 100:1, or more than 1 GiB in all). clamd heuristics now map to reasons: `Heuristics.Limits.Exceeded.*` → `LIMIT_EXCEEDED`, `Heuristics.Encrypted.*` → `ENCRYPTED`. Jazzer targets run their stored inputs in PR runs and fuzz five minutes each in a new nightly job.
