# 0012 — Container base images and image signing

## Context and problem statement
AGENTS §4 / E04 scope require images that are minimal, non-root, read-only-root-filesystem friendly and **signed**, with an SBOM attached, so that SaaS, dedicated and on-prem installs (including air-gapped ones) can verify them. Research: `epic-04-ci-and-supply-chain/research.md §R14`.

## Decision outcome

**Images**

| Image | Base | Notes |
|---|---|---|
| Backend | `gcr.io/distroless/java25-debian13:nonroot`, pinned by digest | Spring Boot layered jar (`-Djarmode=tools extract --layers`); runs as uid 65532; `JAVA_TOOL_OPTIONS` sets `-XX:MaxRAMPercentage=75`; `/tmp` is a writable volume |
| Web | `nginxinc/nginx-unprivileged:1.31.6-alpine3.24`, pinned by digest | Static SPA plus `/api` reverse proxy to the backend. Security headers are generated from `web/security-headers.json` at image build. Runs as uid 101 on port 8080. |

Both images:
- run on a read-only root filesystem with `emptyDir`/tmpfs mounts;
- carry no shell in the backend image;
- carry OCI labels (source, revision, version, licences).

**Signing with a cosign key pair** (no keyless signing):
- Release CI signs the **digest**: `cosign sign --key env://COSIGN_PRIVATE_KEY --tlog-upload=false`.
- It attaches two signed attestations: the CycloneDX SBOM and the SLSA provenance.
- `cosign.pub` is published in the repository (`deploy/cosign.pub`) and with each release.
- Customers verify offline: `cosign verify --key cosign.pub --insecure-ignore-tlog <image@digest>`.
- The key pair is generated by the owner (`cosign generate-key-pair`). The secrets `COSIGN_PRIVATE_KEY` and `COSIGN_PASSWORD` go into GitHub; the release workflow refuses to publish unsigned images.

**Registry:** GHCR (`ghcr.io/nazihar/memo-{backend,web}`) for SaaS, dev and staging. On-prem customers receive the images as signed OCI archives (Phase 7).

### Consequences
- Good: verification works without public infrastructure; minimal attack surface.
- Bad: no shell in the backend image, so debugging uses ephemeral debug containers (`kubectl debug`).
- Bad: the signing key must be rotated and protected. It moves to KMS/HSM in Phase 7.

### Confirmation
- PR: both images build and pass a Trivy image scan with no critical or high findings.
- Release: `cosign verify` with `deploy/cosign.pub` succeeds in the release job.
