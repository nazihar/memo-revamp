# E07 Tenant lifecycle and administration — log

## 2026-11-08
- E06 PR #28 is CI-green and waits for the owner's merge go-ahead; E07 starts on `feat/1a-e07-tenant-admin`, stacked on E06 (it builds on the mail settings).
- Plan written: research (R17 terminology, R18 operator separation, suspension, audit export, branding contrast, language packs), ADR-0031 (operator path), ADR-0032 (terminology overrides), ADR-0033 (audit viewer and export), design, threat model, tasks, test plan. Gate delegated (overview Q1).
- Decisions worth knowing:
  - Operators use the same application on their own host (`admin.<base domain>`), with their own accounts, cookie, session principal and filter chain. Their requests run only in platform scope, where every tenant table's RLS returns nothing; the one write into a tenant (the first admin's invitation) goes through a single class that refuses once the tenant has an active admin.
  - A dedicated database role for operators was considered and deferred to Phase 7: every install's DBA-run role script would change, and `SET LOCAL ROLE` can be reset by the code it guards against.
  - The first operator is created by a command mode of the backend image (`operator-invite`), which prints the enrolment link to its own output, not to the log.
  - Terminology overrides are term arguments with translator-owned defaults and Arabic gender through ICU `select`, not per-tenant message overlays.
  - Branding is its own module, because `files` already depends on `tenancy`.
  - Language packs stay split per locale (the English catalogue is 7 KB gzip); `i18n:verify` gets a size limit as the trigger for per-route splitting.
- T1 built: operator accounts (`identity_operator`, platform-scope RLS), enrolment link from the `operator-invite` command, password + forced TOTP enrolment, lockout (5 in a row, 30 minutes), step-up, operator cookie `MEMO_OPERATOR` chosen by host, a separate security chain for `/api/v1/platform/**`, host routing in the tenant resolution filter, a demo operator. The authorisation matrix now runs files with `host: platform` on the operator host with their own subjects (50 new cells, 542 in total).
- Findings:
  - Both hosts share one Spring Session table, so a tenant session id sent under the operator cookie name does load a session there. What keeps them apart is the principal attribute: on the operator host only `memo.operator` is read, on tenant hosts only `memo.principal`. `OperatorPathIT` sends each side's session id under the other's cookie name to prove it.
  - The per-account login rate limit (10 per 15 minutes) would answer 429 before a lock at 10 failures could ever be seen; operators now lock at 5.
  - Operator tables follow the module prefix rule (`identity_operator`, not `platform_operator` as first drafted); the one-time link is a hash on the operator row instead of a separate token table.
- T2 built: `platform` module (registry list and view, create with defaults and first-admin invitation, rename, suspend, resume, re-invite), `TenantLifecycle` in tenancy, resolver caching the status with cross-node eviction (a new `TenantCaches.onEvict` hook on the LISTEN/NOTIFY channel), 403 `tenant-suspended` from the resolution filter, sessions deleted in the suspension's transaction, suspended tenants' tasks re-queued an hour later as fresh executions (db-scheduler's `removeAndScheduleNew`), so pauses never count as failures. Matrix 577 cells.
- Findings:
  - No new RLS policy was needed after all: lifecycle changes run in the tenant's own scope under `tenant_self`, with the tenant-chain entry in the same transaction; the platform chain is written afterwards in platform scope. ADR-0031 updated.
  - Spring Modulith treats `identity.operator` as internal; the demo seeder and the platform module use it, so it is now a named interface.
  - A controller-scoped `@RestControllerAdvice` loses to the global advice's catch-all unless it is ordered first.
  - `SuspendedTenantIT` walks every mapped tenant endpoint (over 50) on a suspended host and expects 403 from each: the suspended-tenant cases of the authorisation matrix, without a column per file.
- T3–T5 backend built: security settings API (ranges in one `SecurityLimit` table read by sign-in, password policy and lockout; lockout thresholds are tenant settings now), language defaults, terminology (`tenancy_term`, `/terms`, `/admin/terms`, term placeholders in emails), `branding` module (`tenant.logo` purpose, colours checked against WCAG contrast in both themes, public `/branding` and `/branding/logo`), audit query API and the verifiable ZIP export, platform audit viewer. A new `FileContents` API lets an owning module stream its own file (the public logo). Matrix 613 cells.
- Findings:
  - The export records `audit.exported` before the first byte is written, so no export goes unrecorded; an unfiltered range is widened to the full sequence span between its first and last entry, because commit order and timestamps can disagree at the edges.
  - `AuditExportIT` verifies exports with code written from `VERIFY.md` alone, not with memo's own verifier, and catches a one-character change in an entry even when the manifest's file hash is recomputed.
  - Email rendering runs outside any transaction (no transaction is held while talking to the relay), so term lookups open their own read transaction; `MailDeliveryIT` caught it.
  - Endpoints that return `ResponseEntity<Any>` (because they also answer with problems) need an explicit 200 schema, or the generated web client types their body as `unknown`.
- T6, T7 web built: operator console under `/platform` with its own frame, sign-in (password, TOTP, first enrolment), enrolment link page, organisations list and search, new organisation form, organisation page (rename, suspend with a confirmation naming the effects, resume, first-admin invitation), platform audit; tenant admin console: `/admin` overview cards by permission, security settings with ranges, branding (shared `FileUpload` component, live contrast per theme, colours applied through CSS custom properties), language and terms (Arabic gender column), audit viewer with filters and the ZIP export; a tenant gate that shows the suspended notice and sends the operator host to the console. Org screens take the organisation's terms. English and Arabic complete; `i18n:verify` now also checks catalogue size (9.4 and 11.1 KiB gzip against 15).
- Findings:
  - `formatjs verify --structural-equality` requires the same arguments in every language, so where Arabic must agree with a term's gender, the English text is wrapped in a one-branch `select` on the gender argument; translators see where agreement happens.
  - The brand colour cannot be set with an inline style (strict CSP), but `style.setProperty` on the root element is CSSOM and allowed; tokens.css reads `--brand-light` / `--brand-dark`, so the theme switch needs no script.
